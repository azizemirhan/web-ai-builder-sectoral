# Section Name

Design Process

# Sector

Architecture & Interior Design

# Prefix

ARC

# Purpose

Explain how a project moves through the studio: the phases a client passes through, from first
conversation to completion.

# Visitor Intent

The visitor is trying to understand what working with the practice would actually involve, and in
what order.

# Content Responsibility

The process sequence: each phase named, placed in order, described concisely and supported
visually.

# In Scope

- Named phases in a clear order
- A concise description per phase
- Imagery supporting each phase
- Optional interaction that moves through the sequence

# Out Of Scope

- A global site header, primary navigation or footer
- **The service set**, which belongs to S03 — process explains *how*, not *what is offered*
- Programme, schedule or work-stage documentation used as the section's visual language
- Fabricated durations, milestones or deliverable guarantees

# Expected Structural Diversity

| Variant | Direction |
| --- | --- |
| `ARC-S06-001` | Universal / Safe |
| `ARC-S06-002` | Premium / Editorial |
| `ARC-S06-003` | Structured / Visual Modular |
| `ARC-S06-004` | Conversion-led |
| `ARC-S06-005` | Art-directed / Distinctive |

These are authoring and research directions, not production enums, and the study IDs do not change
with them. The five studies must differ structurally. They must not become five colour schemes,
five font themes, five cosmetic variants, or five copies of one grid with the content swapped.

In this section:

- **003** carries a longer process through modular phase blocks, disclosure or a stepped
  navigation — not by turning each phase into a field table.
- **005** is an art-directed process composition: numerals, imagery, alternating rhythm, spatial
  progression. Not a programme matrix, schedule or work-stage sheet.

**Recorded correction.** `ARC-S06-003` and `ARC-S06-005` were reviewed as too technical and too
text-heavy; 005 carried no media at all. Future direction for this section favours clear visual
progression, image-supported phases, timelines, cards, alternating compositions, interactive steps
and concise phase descriptions.

# Architecture Direction

Sector direction: `../ARCHITECTURE-DESIGN-DIRECTION.md`.

`ARC-S06-002` — numerals, serif headings and one image per stage — is the reference for the
direction this section should take. Programme, schedule and drawing-document aesthetics are not
the default here.

# Section Shell

Section only. No global header, navigation or footer.

# Media Relationship

Expected. Each phase should be able to carry an image; a process presented with no media at all is
the failure mode this section has already produced.

# Interaction Notes

Optional. Stepping, tabs or scroll-linked progression are justified, and every phase must remain
readable without script.

# Responsive Considerations

A horizontal timeline needs a real narrow-width form — a stacked sequence that keeps the order
legible — not a shrunken rail. Phase numbering must survive the reflow.

# Authoring Questions

- **Primary visual element:** the phase imagery and the visual rhythm of the sequence.
- **Immediate understanding:** what happens first, and roughly what the journey looks like.

Full authoring question list: `../ARCHITECTURE-DESIGN-DIRECTION.md`.
