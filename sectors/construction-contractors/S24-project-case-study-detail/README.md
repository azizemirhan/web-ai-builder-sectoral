# Section Role

The body of one project page: what changed between the drawing and the building, who decided each
change, and who paid for it.

# The Boundary With S13, Which Governs Everything Here

`S13 Case Studies` already owns named jobs and the device *what we found / what we chose / what it
cost us*, compressed to one decision per case. **This section is not that, at greater length.**

| Section | What it owns |
| --- | --- |
| `S13` Case Studies | **Several jobs**, one decision each |
| `S21` Subpage Hero | Which page this is, and its promise: *the decision this one got wrong* |
| `S24` Project Detail | **One job's register of change**, and who caused each entry in it |

`S21`'s page description promises the reader the decision this project got wrong. **This section is
where that promise is kept.**

# The Governing Constraint — The Record Worth Having Is The Difference

    Every project page shows what was built. The record worth having is the list of
    things that changed between the drawing and the building, and who decided each one.

Those things exist on every job, they are written down as they happen, and **nobody publishes them.**
They are the only content on a project page that a reader with a similar building could not have
guessed.

# The Four Classes Of Change

| Class | Who decided | Who paid |
| --- | --- | --- |
| **Found on opening up** — the building was not what the drawings said | Us and the designer, inside a day | The client, and we said so before we did it |
| **The client changed their mind** — entirely normal, and stated without complaint | The client | The client. *The thing worth publishing is how quickly it was priced, not that it happened* |
| **A design that could not be built as drawn** — the detail worked on paper | The designer, on our proposal | Usually nobody, if it is caught before anything is ordered |
| **We got it wrong** | **Us** | **Us** |

The fourth class is why the section exists. It is the class nobody publishes, and it is the one
`S21`'s hero has already promised the reader.

# What Is Real, And What May Not Be Invented

The catalog's standing resolution — **reserve the specifics, author the apparatus** — applied to a
page that has to carry a real job:

| Element | Treatment |
| --- | --- |
| The four classes, why each happens, and how each is handled | **Real** |
| Who decided and who paid, by role | **Real** |
| The refusals | **Real, and kept** |
| Project name, client, dates, values, the particular change in each class | **Reserved fields** |
| The client's own words | **Reserved quotation** — the `S12` rule: reserve the quotation, author the apparatus |
| Media | **Reserved areas.** One of the work in progress; **never a pair** |
| Any value, duration, percentage or programme figure | **Forbidden** |
| A client logo | **Forbidden** — anti-pattern two |
| A before-and-after pair | **Forbidden** — anti-pattern ten |

# The Signature Refusal

> **Delivered on time and on budget** is not a claim about a project. It is a claim about a page.
>
> A job with no variations is a job nobody has looked at. Every project has a register of change; the
> only question is whether the firm will show it to you.
